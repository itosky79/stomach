# v2 ロードマップ

v1.0（フォルダ直下の `index.html`、タグ `v1.0`）はそのまま残し、改良は `v2/` で行う。v2 は v1.0 の機能をそのまま土台にする。

## 最終目標

VR（Meta Quest）の中で、透視室に立って胃のバリウム検査を体験できるようにする。PC とスマートフォンでも同じものを使える。

## 決めたこと

| 項目 | 決定 |
|---|---|
| VR の動かし方 | **PC 接続**（2026-10-26 変更）。Windows PC の Chrome（または Edge）で公開 URL を開き、Quest を Meta Horizon Link（ケーブルの Link か、無線の Air Link）でつなぐ。描画は PC が行う。ゴーグル単体（Quest のブラウザ）でも開けるが、性能の基準にはしない |
| 対象の VR ゴーグル | Quest 2 と Quest 3 |
| 性能の基準 | 研究室の PC に Link でつないで、ゴーグルの表示回数（72／90 Hz など）を保てること |
| 普段の確認 | PC のブラウザで VR エミュレーター（`?xr=emulate`）を使う。実機での確認は段階の区切りだけ |
| 重さの確認 | アプリ内の表示（`?perf=1`）で行う。ゴーグルの開発者モードは使わない（Link には要らない） |
| 開き方 | 公開 URL で開くのが基本。VR は https の URL からでないと動かない |
| 寸法 | 台・人体・部屋を実物と同じ寸法（メートル）で作る |
| 引き継ぐ決まり | 実際の国試問題だけを出典つきで使う／画面はすっきり保つ／PC での操作は変えない／体位を変えてもカメラは動かさない（VR 酔いを防ぐ原則とも一致する） |
| UI | 機能がそろってから全面的に見直す。それまでは v1.0 の UI のまま |

## 追加する機能

1. ベッドの角度を自由に変える（角度の範囲を広げる。操作卓での操作）
2. 圧迫筒
3. 胃と人体のモデルをリアルにする
4. 胃の型を数種類用意する（v1.0 は鉤状胃・牛角胃・瀑状胃・下垂胃の 4 種類）
5. 胃の伸び縮みなどの質感
6. バリウムの粘度と、胃壁へのへばりつき
7. 地面
8. ベッドに対する X 線管
9. 操作室と術者視点のカメラ

## 段階

| 段階 | 内容 | VR のために | 実機での確認 |
|---|---|---|---|
| 0 | 準備：ファイル分割、three.js を新しい版へ、VR エミュレーターと重さ表示、寸法の決定、胃の物理の小さな試作 | 試作を PC 接続の VR で動かして重さを測る | PC 接続で試作の重さ |
| 1 | 撮影室の土台：地面、透視台（角度の範囲）、X 線管と受像器、操作室、術者視点（7・8・9・1） | 段階の最後に VR で中に入る | 大きさの感覚と酔い |
| 2 | モデル：人体と胃をリアルに、胃の型（3・4） | 研究室の PC で描ける重さに収める | — |
| 3 | 胃の物理：伸展、圧迫筒、粘度とへばりつき（5・2・6） | 圧迫筒は手で持って当てる | 重さ |
| 4 | UI の全面見直し | 画面の UI と VR の中の操作パネルを同時に設計する | — |
| 5 | VR の仕上げ：手での操作、酔い対策、複数人で同じ部屋に入る（任意） | — | 全体 |

順番の理由：
- 部屋の寸法と座標を最初に決めると、後の作業が全部その上に乗る
- 胃の物理（伸び縮み・付着）はモデルの上で計算するので、先にモデルの形を決める
- 圧迫筒は、胃が伸び縮みする仕組みがないと意味がない

## VR と確認用の URL

| URL の末尾 | 内容 |
|---|---|
| （なし） | 普段の画面。VR が使えるブラウザ（Quest のブラウザ）では「VR」ボタンが出る |
| `?xr=emulate` | PC でゴーグルの代わりにエミュレーター（Meta の IWER）を使う。Quest 3 として振る舞う。画面上の操作盤で頭とコントローラーを動かせる |
| `?xr=emulate&device=quest2` | 同じく Quest 2 として振る舞う |
| `?perf=1` | 重さを表示する（fps、1 回の時間、計算の時間、描画の命令数、三角形の数）。VR の中では目の前に板で出る。ほかと組み合わせられる（例：`?xr=emulate&perf=1`） |

VR の中での置き方：1 単位 = 1 cm を 0.01 m として表示する。置き方は「第 1 段階の作業」を参照。透視像・ラベル・重力の矢印は、VR の中ではまだ出さない（第 1 段階の 7 でモニタに出す）。

エミュレーターで出る fps は、2 枚の絵を描く負荷は近いが、Link の転送の負荷は含まない。本番の重さは、PC に Link でつないで `?perf=1` を付けて測る。

## PC 接続での使い方

| 用意するもの | 内容 |
|---|---|
| Windows 10 / 11 の PC | Meta の推奨は Intel Core i7 / AMD Ryzen 7、メモリ 16 GB、NVIDIA RTX 20 シリーズ以降か AMD Radeon RX 6000 シリーズ以降。Intel Arc とワークステーション向け GPU は非対応。最新の条件は Meta のヘルプ「Meta Horizon Link の Windows PC の要件」（https://www.meta.com/help/quest/140991407990979/）で確認する |
| Meta Horizon Link アプリ | PC に入れる（Meta の公式サイトから無料）。OpenXR ランタイムとして有効にする |
| つなぎ方 | USB-C ケーブル（USB 3 推奨）の Link、または無線の Air Link（PC は有線 LAN、ゴーグルは 5 GHz の Wi-Fi） |
| ブラウザ | PC の Chrome か Edge（Firefox は不可） |

手順：
1. PC で Meta Horizon Link アプリを起動し、Quest をケーブルか Air Link でつなぐ（ゴーグルの中で Link を有効にする）
2. PC の Chrome で `https://itosky79.github.io/stomach/v2/` を開く
3. 「VR」ボタンを押すと、ゴーグルの中に透視室が出る。PC の画面にも同じ映像が出るので、周りの人も見られる

「VR」ボタンが出ないときは、Meta Horizon Link アプリが OpenXR ランタイムとして有効になっているか（アプリの設定 → 一般）を確かめる。

## 第 1 段階の作業

| | 内容 | 状態 |
|---|---|---|
| 1 | 実寸（1 単位 = 1 cm）にする。患者を約 170 cm に（胃と体の模型を 1.2 倍、脚を伸ばす） | 済 |
| 2 | 透視台：天板 210 × 75 cm、水平で床から 80 cm、回転軸のまわりに +90°〜−90° 起倒。起こすと天板が長手方向に滑り、端が床に当たらない | 済 |
| 3 | X 線管（オーバーチューブ、SID 120 cm）、受像器、たたんだ圧迫筒、支柱。映像系は胃の位置にある | 済 |
| 4 | 透視室（5 × 6 m、天井 2.8 m）、操作室（隣）、鉛ガラスの窓、55 インチのモニタ、近接操作卓、遠隔操作卓 | 済 |
| 5 | 術者視点（「術者」ボタン。操作室の机の前から窓越しに見る） | 済 |
| 6 | フリーのスティックで +90°〜−90° まで動かせるようにする | 済 |
| 7 | 透視像を透視室の 55 インチと操作室のモニタに出す（VR でも見える） | 済 |
| 8 | VR で台を動かす：コントローラーのスティック（前後で起倒、左右で体軸回転）と、近接操作卓のレバー（グリップで握って奥へ倒すと起きる） | 済 |
| 9 | 段階の最後に VR（PC 接続）で中に入り、大きさの感覚と酔いを確かめる | 未 |

画面では、台が動いて胃が部屋の中を移動しても、カメラが胃を追うので、胃は画面の同じところに見える（「体位を変えてもカメラは動かさない」の決まり）。カメラが操作室の側に出たときは、仕切り壁を隠して透視室が見えるようにしている。

VR では、部屋の床を現実の床に合わせ、回転軸から窓の側へ 130 cm の位置に立って台のほうを向く。部屋は動かず、台が起倒して患者が動く。

VR の操作：
| 操作 | 動き |
|---|---|
| スティックを前／後ろ | 台を起こす／倒す（いっぱいで 20°/秒） |
| スティックを左／右 | 体軸回転（いっぱいで 60°/秒） |
| 近接操作卓（台の頭側、左手前）の黄色いレバーをグリップで握り、奥へ／手前へ動かす | 台を起こす／倒す |

透視像のシェーダは厚みを cm で数えるので、VR で部屋を 0.01 倍にしているときも、透視像を描く間だけ元の大きさに戻している。

## 胃の物理の試作（proto/physics/）

本体とは別の 1 ページ。URL は `…/stomach/v2/proto/physics/`。

- 胃：J 字の管と両端の半球。位置ベースの柔らかい物体として、辺の長さ・体積（ガスの圧）・元の形へ戻る力で形を保つ
- 圧迫筒：先端の直径 10 cm。筒の先より奥に入った前壁を押し戻す。背側は台で支える。画面ではマウスを押し続けて押す。VR ではコントローラーの先が筒の先端
- バリウム：液面は、液の体積が合う高さを二分法で求める。液に浸かった壁は白くなり、液から出ると粘度に応じて流れ落ち、付着の強さに応じて薄い層が残る
- 操作：粘度・付着・バリウム量・ガス量・傾き・回転・細かさ（粗い／普通／細かい）・視点
- URL に `?res=0`（粗い）・`?res=1`（普通）・`?res=2`（細かい）を付けると、最初の細かさを選べる。`?xr=emulate` も使える
- 重さは画面の左上に常に出る。VR の中では右前の板に出る

### 実機での測り方（PC 接続）

1. 下の「PC 接続での使い方」のとおり Quest を PC につなぎ、PC の Chrome で `…/v2/proto/physics/?res=0` を開いて「VR」を押す
2. 右前の板の fps を読む（ゴーグルの表示回数、72 や 90 前後が出れば合格）。胃をコントローラーで押しながらも読む
3. VR を出て、`?res=1`、`?res=2` で同じことをする
4. 3 つの fps を記録する。どの細かさまで表示回数を保てるかで、第 3 段階で使える胃の細かさが決まる

PC での参考値（この開発環境はグラフィックを専用部品なしで描くので、fps そのものは目安にならない）：物理の計算時間は、粗い 590 頂点で約 2 ms、普通 1762 頂点で約 5 ms、細かい 4162 頂点で約 10 ms。

│   ├── iwer.LICENSE         IWER のライセンス（MIT）

    ├── scene.js      体表・骨格・患者・透視台
    ├── sim.js        状態と流体（バリウムとガス）の計算
    ├── camera.js     カメラと視点の操作
    ├── xray.js       透視像とフィルム撮影

three.js は ES モジュールなので、v2 は **ファイルを直接開いても（ダブルクリック）動かない**。公開 URL か、手元で http サーバーを立てて開く。直接開いたときは、その旨を画面に出す。

いまは 1 本のプログラムを順に分けただけなので、どのファイルも同じ名前の変数や関数を共有している（THREE も `window.THREE` として渡している）。ファイル同士の独立は、第 1 段階で部屋を作り直すときに合わせて進める。
