# v2 ロードマップ

v1.0（フォルダ直下の `index.html`、タグ `v1.0`）はそのまま残し、改良は `v2/` で行う。v2 は v1.0 の機能をそのまま土台にする。

## 最終目標

VR（Meta Quest）の中で、透視室に立って胃のバリウム検査を体験できるようにする。PC とスマートフォンでも同じものを使える。

## 決めたこと

| 項目 | 決定 |
|---|---|
| 対象の VR ゴーグル | Quest 2 と Quest 3 |
| 性能の基準 | Quest 2 で滑らかに動くこと（1 秒に 72 回以上描く）。Quest 3 では余った性能で画質を上げる |
| 普段の確認 | PC のブラウザで VR エミュレーター（`?xr=emulate`）を使う。実機での確認は段階の区切りだけ |
| 重さの確認 | アプリ内の表示（`?perf=1`）で行う。ゴーグルの開発者モードは使わない |
| 開き方 | 公開 URL で開くのが基本。VR は https の URL からでないと動かない |
| 寸法 | 台・人体・部屋を実物と同じ寸法（メートル）で作る |
| 引き継ぐ決まり | 実際の国試問題だけを出典つきで使う／画面はすっきり保つ／PC での操作は変えない／体位を変えてもカメラは動かさない（VR 酔いを防ぐ原則とも一致する） |
| UI | 機能がそろってから全面的に見直す。それまでは v1.0 の UI のまま |

## 追加する機能

1. ベッドの角度を自由に変える（角度の範囲を広げる。操作卓での操作）
2. 圧迫筒
3. 胃と人体のモデルをリアルにする
4. 胃の型を数種類用意する（v1.0 は鉤状胃・牛角胃・瀑状胃・下垂胃の 4 種類）
5. 胃の伸び縮みなどの質感
6. バリウムの粘度と、胃壁へのへばりつき
7. 地面
8. ベッドに対する X 線管
9. 操作室と術者視点のカメラ

## 段階

| 段階 | 内容 | VR のために | 実機での確認 |
|---|---|---|---|
| 0 | 準備：ファイル分割、three.js を新しい版へ、VR エミュレーターと重さ表示、寸法の決定、胃の物理の小さな試作 | 試作をゴーグルで動かして重さを測る | Quest 2 で試作の重さ |
| 1 | 撮影室の土台：地面、透視台（角度の範囲）、X 線管と受像器、操作室、術者視点（7・8・9・1） | 段階の最後に VR で中に入る | 大きさの感覚と酔い |
| 2 | モデル：人体と胃をリアルに、胃の型（3・4） | ゴーグル単体で描ける重さに収める | — |
| 3 | 胃の物理：伸展、圧迫筒、粘度とへばりつき（5・2・6） | 圧迫筒は手で持って当てる | 重さ |
| 4 | UI の全面見直し | 画面の UI と VR の中の操作パネルを同時に設計する | — |
| 5 | VR の仕上げ：手での操作、酔い対策、複数人で同じ部屋に入る（任意） | — | 全体 |

順番の理由：
- 部屋の寸法と座標を最初に決めると、後の作業が全部その上に乗る
- 胃の物理（伸び縮み・付着）はモデルの上で計算するので、先にモデルの形を決める
- 圧迫筒は、胃が伸び縮みする仕組みがないと意味がない

## ボトルネック

| | 内容 | 対策 |
|---|---|---|
| 1 | 胃の物理を Quest 2 で動かすこと。本物の流体計算は間に合わない | 見た目と学習に要る振る舞いだけを簡略化して再現する。第 0 段階で試作して測る |
| 2 | 粘度やへばりつきの「正しさ」を確かめる実測データがない | 物理的な正確さより「実際の透視像と見た目が合う」ことを目標にし、技師の先生や指導教員に評価してもらう |
| 3 | リアルな 3D モデルの調達 | 自作か公開データ（BodyParts3D など、CC BY-SA）かを決める。CC BY-SA だと v2 も同じ条件で公開することになるので、指導教員に確認する |
| 4 | VR の確認は実機でしかできないことがある（酔い・重さ・大きさの感覚） | 普段はエミュレーター。実機は段階の区切りでまとめて確認する |
| 5 | 規模が大きい | 次の発表までに見せる最小限を決めて先に作る |

|---|---|---|

| 大きさの感覚 | △ | ○ |

## 第 0 段階の作業

| | 内容 | 状態 |

| 1 | `v2/` をファイルに分ける（見た目と動きは v1.0 のまま） | 済 |

| 3 | VR エミュレーター（`?xr=emulate`）と重さの表示（`?perf=1`）を組み込む | 未 |

## まだ決めていないこと

- 「コンソールの傾き調整」が指すもの（操作卓のレバーか、画面の操作パネルか）
- ベッドの角度の範囲（+90°〜−90° か、今の −30° までか）
- 術者視点のイメージ（操作室の窓越しか、操作卓の前でモニタと窓の両方を見るか）
- VR で何を優先するか（操作室から操作する／患者のそばで体位変換や圧迫をする／両方）
- 3D モデルを自作するか、公開データを使うか
- 次の発表の時期と、そこで見せる最小限
- NAS に置いた ZIP から v2 を開く方法（必要になったら決める）

## v2 のファイル構成

```
v2/
├── index.html        画面の骨組み（HTML）
├── ROADMAP.md        このファイル
├── lib/
│   ├── three.module.min.js  three.js 0.186.1（ES モジュール、1 ファイルにまとめたもの）
│   └── three.LICENSE        three.js のライセンス（MIT）
├── css/app.css       見た目
└── js/
    ├── boot.js       three.js を読み込み、下のファイルを順に読み込む
    ├── data.js       胃型・体位・撮影手順の定義
    ├── questions.js  収録問題（国試の過去問）
    ├── model.js      胃の管モデルの生成
    ├── scene.js      体表・骨格・患者・透視台
    ├── sim.js        状態と流体（バリウムとガス）の計算
    ├── camera.js     カメラと視点の操作
    ├── xray.js       透視像とフィルム撮影
    ├── labels.js     部位名のラベル
    ├── ui.js         コンソール（学習・手順・フリー・問題）
    ├── main.js       初期化と描画ループ
    └── fail.js       3D を表示できないときの案内（最初に読み込む）
```

three.js は ES モジュールなので、v2 は **ファイルを直接開いても（ダブルクリック）動かない**。公開 URL か、手元で http サーバーを立てて開く。直接開いたときは、その旨を画面に出す。

いまは 1 本のプログラムを順に分けただけなので、どのファイルも同じ名前の変数や関数を共有している（THREE も `window.THREE` として渡している）。ファイル同士の独立は、第 1 段階で部屋を作り直すときに合わせて進める。
